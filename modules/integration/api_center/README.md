# Azure API Center

Composes an Azure API Center service and the complete catalog hierarchy with
AzAPI 2.13.0:

1. service
2. workspace (including `default`)
3. environment and API
4. API version and definition
5. API deployment
6. optional service metadata schema

AzureRM 5.14 has no API Center resources, so this module deliberately uses
AzAPI. Every resource and the `importSpecification` action use the stable ARM
API version **`2024-03-01`**. The 2024-06-01 preview only adds API sources and
soft-delete restore behavior; neither is required for this registration
contract, so preview APIs are rejected rather than silently introduced.

## Exact resource types

| ARM resource | API version |
| --- | --- |
| `Microsoft.ApiCenter/services` | `2024-03-01` |
| `Microsoft.ApiCenter/services/workspaces` | `2024-03-01` |
| `Microsoft.ApiCenter/services/workspaces/environments` | `2024-03-01` |
| `Microsoft.ApiCenter/services/workspaces/apis` | `2024-03-01` |
| `Microsoft.ApiCenter/services/workspaces/apis/versions` | `2024-03-01` |
| `Microsoft.ApiCenter/services/workspaces/apis/versions/definitions` | `2024-03-01` |
| `Microsoft.ApiCenter/services/workspaces/apis/deployments` | `2024-03-01` |
| `Microsoft.ApiCenter/services/metadataSchemas` | `2024-03-01` |

The schema was checked against the official Azure REST API specifications.
`examples/tests/schema/api_center_schema_test.py` repeats the resource-path,
writable-body, enum, identity, and source-literal checks.
`examples/tests/schema/api_center_arm/main.tf` additionally runs AzAPI 2.13
embedded ARM schema validation with a real provider plan and no refresh/apply.

## Usage

```hcl
integration = {
  api_center = {
    catalog = {
      name           = "ai-catalog"
      resource_group = { key = "integration" }

      workspaces = {
        default = {
          name  = "default"
          title = "Default"
          environments = {
            production = {
              name  = "production"
              title = "Production"
              kind  = "production"
            }
          }
          apis = {
            ai = {
              name  = "ai"
              title = "AI API"
              kind  = "rest"
              versions = {
                v01 = {
                  name            = "v01"
                  title           = "Version 1"
                  lifecycle_stage = "production"
                  definitions = {
                    openapi = {
                      name  = "openapi"
                      title = "OpenAPI"
                      specification = {
                        value = "{\"openapi\":\"3.0.0\",\"info\":{\"title\":\"AI\",\"version\":\"1\"},\"paths\":{}}"
                      }
                    }
                  }
                }
              }
            }
          }
        }
      }
    }
  }
}
```

## Reference modes

- `resource_group`: direct `name`, local `key`, or remote `key` + `lz_key`.
- `service`: direct `service_id`/`service.id`, or remote `service.key` +
  `lz_key`.
- deployment `environment`: direct `environment_id`/`environment.id`, or a
  local workspace environment key.
- deployment `definition`: direct `definition_id`/`definition.id`, or local
  `api version key` + `definition key`.
- identity: direct `identity_ids`, local `managed_identity_keys`, or remote
  `managed_identities` with `key` and `lz_key`.

## Identity

The stable service schema supports `SystemAssigned`, `UserAssigned`, and
`SystemAssigned,UserAssigned`. A user-assigned identity requires one or more
resolved identity resource IDs. Identity principals are returned as
non-sensitive metadata.

## Inputs

| Input | Description |
| --- | --- |
| `global_settings` | CAF naming, regions, and global tags. |
| `client_config` | Landing-zone key and subscription ID. |
| `settings` | Service, identity, workspace, catalog, deployment, and timeout maps. |
| `remote_objects` | Resource groups, existing API Centers, and managed identities. |
| `base_tags` | Base tags merged on the service. |

All resources accept a `timeouts` object with optional `create`, `read`,
`update`, and `delete` duration strings. Specification import accepts its own
`specification.timeouts`.

## Outputs

Outputs expose the service and all child IDs/names plus service identity
metadata. No key, token, subscription credential, OpenAPI secret, or APIM
subscription key is emitted.

## Integration notes

- The Microsoft.ApiCenter 2024-03-01 service schema has no
  `publicNetworkAccess`, private endpoint, or diagnostic settings payload.
- Azure Monitor/private-link integration is therefore not generated by this
  module. Root deployments can target the service through the generic RBAC
  `api_centers` scope resource key; direct consumers can use its returned ID.
- AzureCAF 4 has no native API Center resource definition. The module uses the
  compatible resource-group naming envelope with `use_slug = false` and adds
  ARM name checks during service planning.
- `2024-06-01-preview` API source discovery is intentionally out of scope.
