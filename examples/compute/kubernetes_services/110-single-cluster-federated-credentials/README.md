# AKS workload identity and node-pool compatibility

This example creates an AKS cluster, a user node pool, a user-assigned identity
and a federated credential using the cluster's OIDC issuer.

The system pool exercises legacy `container_log_max_line` and
`transparent_huge_page_enabled`. The user pool supplies both old and current
names to demonstrate that `container_log_max_files` and `transparent_huge_page`
take precedence. Its sysctl setting also exercises nested node-pool configuration.
Omitted node provisioning settings retain manual provisioning.

From the repository root:

```bash
terraform -chdir=examples test -test-directory=./tests/mock \
  -var-file=../examples/compute/kubernetes_services/110-single-cluster-federated-credentials/configuration.tfvars \
  -verbose
```

For a live lifecycle, use an isolated Terraform state and unique naming prefixes.
The node resource group name must also be unique because it is passed directly
to Azure rather than generated by CAF.
